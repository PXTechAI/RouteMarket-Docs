这篇文档只讲第一批最重要的生产部署信息：**域名、服务、镜像和发布链路如何对上。**

## 当前公开域名

生产环境中的主要公开域名如下：

- `routemarket.ai` -> `web:3000`
- `console.routemarket.ai` -> `web:3000`
- `docs.routemarket.ai` -> `docs:3000`
- `api.routemarket.ai` -> `gateway:3002`

其中 `docs.routemarket.ai` 现在已经是独立的 Fumadocs 站点，而不是主站里的占位页。

## 当前主要服务

RouteLab 当前生产应用栈里包括：

- `web`
- `docs`
- `core-api`
- `gateway`
- `connector-service`
- 若干 worker
- PostgreSQL / Redis / PgBouncer / 监控组件

## docs 站是怎么上线的

`docs` 站的发布链路现在是：

1. GitHub Release 触发镜像构建
2. Actions 构建 `docs` target
3. GHCR 推送 `ghcr.io/lizhug/docs:<tag>` 和 `ghcr.io/lizhug/docs:prod`
4. Docker Swarm stack 使用 `ghcr.io/lizhug/docs:prod` 启动 `docs` 服务
5. Caddy 将 `docs.routemarket.ai` 反向代理到 `docs:3000`

## 应用栈和边缘入口

目前线上边缘代理使用的是 Caddy，应用栈通过 Docker Swarm 运行。

对 docs 站来说，最关键的两段关系是：

- 应用栈里有 `docs` 服务
- Caddy 里有 `docs.routemarket.ai` 的反代规则

## 必要的环境约定

文档站当前最关键的公开环境变量是：

```bash
NEXT_PUBLIC_DOCS_SITE_URL=https://docs.routemarket.ai
```

而整个平台的主站 / console / docs 域名约定仍然保留在统一部署环境里，例如：

```bash
NEXT_PUBLIC_WWW_HOST=routemarket.ai
NEXT_PUBLIC_CONSOLE_HOST=console.routemarket.ai
NEXT_PUBLIC_DOCS_HOST=docs.routemarket.ai
NEXT_PUBLIC_SITE_DOMAIN=routemarket.ai
```

## 数据与依赖

RouteLab 生产栈本身还依赖这些基础设施：

- PostgreSQL
- Redis
- PgBouncer
- TLS 证书
- 反向代理
- GHCR 镜像仓库

## 上线检查清单

如果你要验证 docs 站是否成功上线，至少检查：

1. `docs` 镜像是否成功构建并推送
2. Swarm stack 是否已经 redeploy
3. `docs` 服务是否 healthy
4. `docs.routemarket.ai` 是否能正常打开
5. 文档首页与几个内容页是否都能访问
